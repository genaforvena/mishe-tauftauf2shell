# Frontier brief: lzxwindow2shell — CVE-2026-125742 (7-Zip LZX window-desync heap OOB write)

**Status: STAGED 2026-11-27 W307, unowned. Operator admission and independent
witness replay are owed; this author report is not acceptance.** The two-pane
window 206 (panes on the inner socket) is live and registered. Grade at
handoff: **R1 ✓ / R2 ✓ / R3 ✓ (GCC ASan WRITE of 4096 in the verbatim pinned
sink; caller/input shape generated by the harness) / R4 — / R5 —**. Claims
below are tied to pinned bytes and local observations; advisory prose is
labeled as claim.

## Verified ground truth (sources read 2026-11-27)

- **Claim sources:** GHSA `https://github.com/advisories/GHSA-vfpw-mfgh-fqwf`,
  NVD `https://nvd.nist.gov/vuln/detail/CVE-2026-125742`, OSV
  `https://api.osv.dev/v1/vulns/CVE-2026-125742`, fix/release commit
  `https://github.com/ip7z/7zip/commit/d3296e39e1f1f92c7b41c0c3848e65640428d42d`,
  researcher writeup
  `https://potion-brew.pages.dev/posts/7zip-cab-lzx-window-desync-rce/`.
- **Versions:** affected `26.05` and earlier (CVSS 8.5 HIGH, CWE-787); fixed
  `26.06`. Vulnerable tag `26.05` is commit
  `b88c6bc09339de32f7d18bbab900686b244f42ba`; fixed tag `26.06` is commit
  `d3296e39e1f1f92c7b41c0c3848e65640428d42d` (both verified via GitHub tags
  API, pinned in `pins/tags.json`). There is no standalone small upstream fix
  commit: the security delta is bundled in the 26.06 release commit.
- **Claimed primitive:** a continuation CAB folder reconfigures the LZX window
  from 21 bits (2 MiB) to 15 bits (32 KiB) while `_keepHistory=true`; the stale
  `_pos` (published `0x14A420`) makes the unsigned `outSize > _winSize - _pos`
  check wrap, so the decode writes ~1.3 MB past the new window. The writeup
  claims a FILE-vtable/FSOP chain to `system()` with ASLR-on success rates;
  that chain is a claim, not reproduced here.
- **Fix (source-bound):** verbatim diff of the two pinned files adds
  `_pos(0)` and `_overDict(false)` to the constructor and, critically,
  `_pos = 0; _overDict = false;` in `Set_DictBits_and_Alloc()` immediately
  after `_winSize = 0`, before the new allocation. Four added lines, one file.
  `pins/fix.patch` is a frontier-generated diff of pinned tag files, not an
  upstream patch artifact.

## Source-bound mechanism (pinned bytes)

Vulnerable `CPP/7zip/Compress/LzxDecoder.cpp:1464`:
`if (outSize > _winSize - _pos) return S_FALSE;` with `_pos` stale and greater
than the shrunken `_winSize`. The uncompressed branch at `:1396` then calls
`_bitStream.CopyTo(_win + _pos, next)` — an unbounded `memcpy` at a pointer far
past the 32 KiB allocation. Fixed `:1503-1508` clears `_pos` on the size change,
so the same call writes inside the new window. The decoder body is otherwise
byte-identical across pins.

## Local observation (2026-11-27 W307, GCC ASan and plain controls)

`harness.cpp` encodes minimal LZX uncompressed blocks from the pinned bit
grammar; no upstream file is edited. It drives the pinned public API through
three phases: a real 1,355,296-byte decode in a 21-bit window, a shrink to
15 bits, then a 4096-byte replay. `sh build-all.sh` builds four binaries;
`sh run-all.sh`: rc 0 **PASS=28 FAIL=0**; runner SHA-256
`a89a11cb7d9818751faf92ec4aeadbfd8ff01f6dbd05301dc754248f8fce2cd8`.

- **Published offset `0x14A420`:** both pins report `PHASE1 pos=1352736`;
  after shrink the vulnerable pin reports `pos=1352736`, the fixed pin `pos=0`.
  Vulnerable replay: ASan `SEGV on unknown address 0x…14a840`, frame raw
  `LzxDecoder.cpp:1396`. Fixed replay: ASan-clean, `PHASE3 pos=4096`.
- **Near offset `0x9000` (ASan redzone):** vulnerable replay reports
  `heap-buffer-overflow`, `WRITE of size 4096`, `4064 bytes after 32800-byte
  region`, raw frame `LzxDecoder.cpp:1396`. Fixed replay is ASan-clean and
  writes at offset 0. This is the graded R3 observation.
- Both pins return `S_FALSE` on the replay because the retained byte-mode
  cursor inflates trailing-byte accounting; preserved as a harness-shape
  negative. Full provenance: `lab/frontier/lzxwindow2shell/PROVENANCE.md`.

## Rung-4 feasibility and cheapest next experiment

Rung 4 is not established: the window buffer and replay block are
harness-generated, no 7-Zip CAB command-line consumer was exercised, and no
chosen-byte readback in a real adjacent object was observed. The cheapest next
experiment for the target mind is to build a two-volume CAB with a continuation
folder that sets the 15-bit window and feed it to a local `7z x` ASan build on
loopback-with-no-network (local file only), then measure whether attacker bytes
land at a chosen offset in a real adjacent object; vulnerable, fixed and safe
folder controls are required. A wire/request path is UNKNOWN. Pointer control,
marker execution and remote command execution are not claimed.
