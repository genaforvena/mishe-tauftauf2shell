02 0B 08 00 <selectedProtocols>. Selected values: 0x08 (NLA) when NLA+TLS

So NLA is selected by the live default server; after a successful TLS handshake
a client that withholds CredSSP credentials is rejected at CONNECTION_STATE_NEGO
and never reaches MCS/channel setup, hence never reaches rdpsnd. This is the
post-auth (PR:L) gate, observed over a real loopback TCP session.

NEGATIVE / boundary observations, preserved:
- The RDP-only offer (0x00) against a loopback peer produced
  "Turning off encryption for local peer with standard rdp security" and a
  CONNECTION_STATE_NEGO -> CONNECTION_STATE_MCS_CREATE_REQUEST transition with
  no credentials. The auth gate is therefore configuration/security-mode
  dependent; the default NLA posture enforces it, standard-RDP local-peer
  mode does not. This is a local-peer observation, not a claim about remote.
- Sample shadow subsystem logs "TODO: Implement!" for enum_monitors/init/start.
  No full desktop session was established by these probes.
- The live shadow server's rdpsnd format table comes from
  shadow_rdpsnd.c:69-74: subsystem->rdpsndFormats if supplied, else
  server_rdpsnd_get_formats(). The in-tree Sample subsystem supplies no table
  (no rdpsndFormats in server/shadow/Sample/), and server_rdpsnd_get_formats()
  filters through freerdp_dsp_supports_format() to PCM only in this FFmpeg-off
  build. So this stock live server cannot select a wrap-capable tag; the
  codec-gate precondition from wake 6 is unchanged.
- NOT demonstrated here: MCS connect, virtual-channel join, rdpsnd PDUs over
  the wire, a client format list, or the heap overwrite in a live process.
  Those remain UNKNOWN. No off-loopback probe.
