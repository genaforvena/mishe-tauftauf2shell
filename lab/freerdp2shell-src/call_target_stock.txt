freerdp2shell wake 20 — chosen indirect call target through the live rdpsnd
wLog object (CVE-2026-114045 / GHSA-3m9q-g533-rqjq)

Question (operator DM #5451): can wake 13/18's controlled dereference reach a
call target or a lab-chosen benign-command side effect on the pinned loopback
build? Answer: YES in the scratch lab build — a chosen function pointer in the
overwritten `s_wLog` is consumed as `log->custom(log->context)` by real FreeRDP
WLog layout code and executes a benign command. This is a LAB-MECHANICS rung-4
result, NOT rung 5: the written bytes come from the lab's server-side
synthetic audio source (wake 17), not from the client wire, and the copy needs
the lab's timing delay. Default posture here is post-auth (-auth, PR:L).

Chosen-byte construction (scratch code at the real CopyMemory site)
------------------------------------------------------------------
The lab synthetic playback buffer (16384 bytes, normally 0xDE) receives:
  +off+0     Name     = pointer to the command string
  +off+8     FilterLevel = 0 (TRACE) so no filter/Names dereference is needed
  +off+40    Appender = original value (NULL; inherited from Parent)
  +off+48    Parent   = original value (live root wLog)
  +off+112   custom   = address of libc system()
  +off+120   context  = pointer to the command string at out_buffer+12000
  out_buffer+12000    "touch /tmp/frw20-rce-marker"
The real CopyMemory then writes these bytes with a 16384-byte chosen span.
No server-side log call was injected: the log is FreeRDP's own client
quality-mode WLog_DBG on the clobbered rdpsnd TAG.

Honest boundary
---------------
- The CLIENT controls the malformed format (wrap) and, via format-record
  count, the target offset (wake 18); it does NOT choose the bytes written.
  The function pointer, argument and command string come from the lab's
  server-side synthetic playback source. Wake 17 source-bounds the copied
  bytes and stride to the server's platform audio capture in stock builds.
- A lab timing delay is still required for a post-write log; a WLOG_FILTER is
  not, because FilterLevel is overwritten. Two of the wLog fields (Appender,
  Parent) are preserved via the playback source so the real appender chain can
  be reached; without that preservation the log faults earlier. This is a
  laboratory call-target demonstration, not a wire-only RCE and not witness
  acceptance.
- Scratch sources were restored after capture; committed wake8 patches,
  their digests and verify_live.sh were not changed. No probe off loopback.
