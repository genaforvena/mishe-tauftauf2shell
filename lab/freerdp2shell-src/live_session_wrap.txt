3. INTEGER WRAP IN THE LIVE SERVER PROCESS
------------------------------------------
Scratch source conditions (wake8-patches/*.patch): server Sample subsystem
supplies an ADPCM-capable rdpsnd table through subsystem->rdpsndFormats, the
same condition as wake 6's harness `subsystem` mode; the client sends a
second SNDC_FORMATS PDU carrying WAVE_FORMAT_ADPCM, nChannels=2,
nBlockAlign=8. Server log, exact:
  [rdpsnd_server_select_format]: realloc failed!
  [rdpsnd_activated]: SelectFormat failed with 12
This is the wrap (`bs = (8 - 7*2)*2/2 + 2 = -4`, widened to
0xfffffffffffffffc; failed realloc, unrolled-back out_frames) observed in a
live FreeRDP server process, reached over the wire through the real parser,
real dispatcher and real shadow activation callback.

4. LIVE-PROCESS HEAP OVERFLOW (ASan)
-----------------------------------
A synthetic audio playback event was injected through the real shadow
message path (SHADOW_MSG_OUT_AUDIO_OUT_SAMPLES -> shadow_client_thread ->
rdpsnd_server_send_samples), standing in for a server audio source; the
Sample subsystem has none. The injected 16384-byte buffer is filled with the
chosen marker 0xDE. Plain build under gdb first showed SIGSEGV at
`__memcpy_avx_unaligned_erms` <- `rdpsnd_server_send_samples` <-
`shadow_client_subsystem_process_message` (live_session_crash_gdb.txt).

The decisive condition was the SNDC_FORMATS `wVersion`. With the client's
default `CHANNEL_VERSION_WIN_MAX`, `rdpsnd_main.c:1277-1278/1285-1286`
invokes `Activated` only after SNDC_QUALITYMODE — after both format PDUs —
so only the malicious record was selected and `out_buffer` stayed NULL
(ASan WRITE SEGV at address zero; preserved negative in the earlier log).
Setting `wVersion=1` in both PDUs makes Activated run after each
SNDC_FORMATS: PDU 1 (benign PCM) allocates the 8820-byte buffer via realloc
in `rdpsnd_server_select_format`, PDU 2 (ADPCM blockalign=8/channels=2)
wraps and fails the realloc without rolling back `out_frames`. Then the
playback event writes OOB. Final ASan report, exact:

  WRITE of size 16384 at 0x525000011374 thread T3

5. HONEST BOUNDARY
------------------
This is a live FreeRDP 3.32.0 server process, on 127.0.0.1, in an ACTIVE RDP
session: the two SNDC_FORMATS PDUs crossed a real virtual channel, the real
dispatcher and parser ran, the wrap occurred in the live process, and ASan
observed a 16384-byte client-data write starting exactly at offset 8820 of
the 8820-byte allocation (first OOB byte is the chosen 0xDE marker).
Conditions that are lab-provided, not stock: `-auth` (no-auth posture), a
subsystem-supplied ADPCM format table (the same explicit condition as wake
6's harness), an ASan build, and a synthetic audio playback event (the
Sample subsystem has no audio source). The write is sequential, so pointer
control and grooming a specific heap object remain UNKNOWN; only the first
OOB byte offset is pinned here. FFmpeg-enabled builds and the live process
under the stock allocator remain UNVERIFIED. Default posture is post-auth
(PR:L, CVSS 8.8); the no-auth lab configuration is the 9.8 case.
