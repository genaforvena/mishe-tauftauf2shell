2. FULL ACTIVE RDP SESSION WITH A REAL CLIENT
--------------------------------------------
Server built with WITH_CLIENT=ON and -DWITH_SAMPLE=ON; client is the
headless client/Sample/sfreerdp target (no X11, no SDL, no FFmpeg):
  freerdp-shadow-cli /bind-address:127.0.0.1 /port:13893 -auth /log-level:DEBUG

3. INTEGER WRAP IN THE LIVE SERVER PROCESS
------------------------------------------
Scratch source conditions (wake8-patches/*.patch): server Sample subsystem
supplies an ADPCM-capable rdpsnd table through subsystem->rdpsndFormats, the
same condition as wake 6's harness `subsystem` mode; the client sends a
second SNDC_FORMATS PDU carrying WAVE_FORMAT_ADPCM, nChannels=2,
nBlockAlign=8. Server log, exact:
  [rdpsnd_server_select_format]: realloc failed!
  [rdpsnd_activated]: SelectFormat failed with 12
This is the wrap (`bs = (8 - 7*2)*2/2 + 2 = -4`, widened to
0xfffffffffffffffc; failed realloc, unrolled-back out_frames) observed in a
live FreeRDP server process, reached over the wire through the real parser,
real dispatcher and real shadow activation callback.

5. HONEST BOUNDARY
------------------
The live-process fault is a write through the wrapped out_frames path, but
the fault address was the zero page: in the live wire sequence the 8820-byte
out_buffer had not been allocated (the harness needs a benign PCM format
selected in a *separate* PDU first). Despite sending two PDUs and forcing a
benign PCM record into the first, the server's coalesced dispatch did not
reproduce that pre-allocation, so the exact `0 bytes after an 8820-byte
region` overflow with client-chosen bytes at chosen offsets remains
demonstrated only in the in-process harness (realwts_subsystem.txt,
realwts_asan_subsystem.txt, wake 6). Live rungs established here: rung 2
(format over the wire), rung 1 in the live process, and a real
memcpy/SendSamples fault (rung 3-adjacent, fault address not the intended
OOB region). Pointer control and stock heap grooming remain UNKNOWN.
Post-auth caveat unchanged: default posture PR:L/CVSS 8.8; the no-auth lab
configuration used for the session is the 9.8 case.
