W186 — chosen-address overwrite of a live FontMapRec.recode function pointer
============================================================================
2026-11-24, libfontenc 7418fa7 (vulnerable) vs 5920c6e (fixed).

Claim
-----
W183 overwrote a live data pointer. FontMapRec (src/X11/fonts/fontenc.h:49-59)
also holds two function pointers:

    unsigned (*recode)(unsigned, void *)   offset 0x10
    char *  (*name)(unsigned, void *)      offset 0x18

The same setCode() store can write all four 16-bit halves of the recode field
of a mapping that parseEncodingFile() has already installed. Calling the
public FontEncRecode() API then jumps to the chosen address.

Layout calibration
------------------
Runner: build-vuln/out-plain, non-PIE probe, MALLOC_MMAP_THRESHOLD_=262144,
setarch x86_64 -R, FONT_ENCODINGS_DIRECTORY pointing at a crafted encodings.dir.
With the seven-mapping input, buffer_base = enc + 0x330 and the live m3 object
sits at buffer_base + 0x20050; m3->recode is at buffer_base + 0x20060.
setCode() index = (from >> 8) * row_size + (from & 0xff). With row_size=258,
from = 0xfe34, 0xfe35, 0xfe36, 0xfe37 gives indices 65584..65587, i.e. the
four 16-bit words at m3->recode. gdb at the earlier crash confirmed the first
word landed exactly: m3->recode read 0x00000000004011d6, the marker address.

Input and method
----------------
marker.c defines a real benign function benign_marker(unsigned, void *) that
writes "BENIGN_MARKER_EXECUTED" to fd 1 and returns 0xabcd1234. run.sh compiles
it -no-pie, reads its address with nm (out/address.txt), and bakes the four
little-endian 16-bit words into crafted.enc as the "to" values of mappings
4..7. The safe control uses SIZE 256 256 with the same mapping structure so
every index stays in bounds. The fixed control uses the same crafted.enc with
build-fixed/out-plain.

Results (out/*.txt, regenerated by run.sh)
------------------------------------------
vuln-crafted rc=0: m3 recode=0x4011d6 equals the marker address; the line
    "m3 recode=0x4011d6 calling... BENIGN_MARKER_EXECUTED" appears and
    recode=2882343476 (0xabcd1234). m1, m2 and m4..m7 keep the library's
    FontEncSimpleRecode address and their normal recode values.
vuln-safe rc=0: every recode field is the library address; no marker.
fixed-crafted rc=0: the fixed guard rejects every out-of-range mapping; no
    marker, and mappings 2..7 recode to 0.

Negative result preserved
-------------------------
An earlier eight-mapping variant appended "0xff00 0xcafe"; that store landed
on the high half of m6->next and crashed install_mapping() at encparse.c:435
(gdb backtrace). The trailing mapping was removed rather than the crash
suppressed: grooming a function pointer and corrupting the mapping list are
different outcomes.

Scope limit
-----------
This is rung 4: a chosen target executed in the lab harness with an ASLR-off,
fixed-malloc-threshold, non-PIE layout and a direct public-API call. The marker
is a lab-chosen function in the probe binary, not a command, a saved return
address, wire input or a privileged process. The W155 ASan trace shows the same
setCode() store inside a live Xvfb, but this control-flow diversion has not
been reproduced inside Xvfb. A layout-independent redirect is blocked: with
ASLR on, heap low 12 bits are stable across runs but bits 12-15 are not
(0x34b0/0x74b0/0xb4b0/0x24b0 observed), while setCode() writes full 16-bit
words from a static file. Rung 5 stays UNKNOWN. Witness has not replayed W186.
