  https://github.com/coturn/coturn/security/advisories/GHSA-74pg-rfh2-5qw5
  (published 2026-05-24, high, CWE-120). Claims a pre-auth stack write from an

  head SHA `1513d7468be275e0bb8a6f488482eaf38701b21b` named in the advisory
  and PR patch is not present in the cloned master history; the merge commit
  is the exact pinned fix here. `46368b3e` is an ancestor of tag `4.10.0`
  (`f07064f9ab7fba2241658054061e63d640f50fdf`), matching the advisory's
  patched version. The advisory's test commit `86e5e727` is an ancestor of
  the pinned vulnerable parent `6e8dd731a7beb3a3b2161923ccb08ab919501ea0`.

## Build and observation

`bash bootstrap.sh` extracts both archives and compiles four variants with
system `cc`, OpenSSL 3.0.13 and libevent 2.1.12-stable: ASan (`-O0 -g
-fno-omit-frame-pointer -fsanitize=address -fno-sanitize-recover=all`) and
unprotected plain (`-O0 -g -fno-stack-protector -D_FORTIFY_SOURCE=0`). The
harness mirrors upstream `fuzzing/FuzzOAuthToken.c` from the fix commit with
a file-reading `main`; inputs are generated by `generate-inputs.py`.

`ASAN_OPTIONS=detect_leaks=0` is set by `run-all.sh`: nonce-256 and nonce-16
controls hit an OpenSSL error-path leak in **both** vulnerable and fixed
builds. That leak is unrelated to the write and is preserved as a negative,
not treated as a pass or a fix regression.

Observed on pinned bytes:

- `runs/vuln-asan-990.out`: rc 1, `AddressSanitizer: stack-buffer-overflow`,
  `WRITE of size 990`, frame `decode_oauth_token_gcm` at
  `client/ns_turn_msg.c:2363`, called from `decode_oauth_token:2485`.
  ASan frame report: destination `dtoken` occupies `[48,456)`; first invalid
  byte is offset 456, underflowing the adjacent `key` object.
- `runs/fixed-asan-990.out`: rc 0, `nonce length too large: 990 > 256`,
  `DECODE_OK=0 NONCE_LEN=0`, no ASan report.
- `runs/vuln-plain-990-chosen.out`: rc 0,
  `key_length=0x4141 mac_key0=0x41 timestamp=0x4141414141414141
  lifetime=0x41414141` — chosen `0x41` bytes land in adjacent struct fields
  after `nonce[256]`. `runs/fixed-plain-990.out` shows all-zero fields.
- nonce-256 and nonce-16 inputs are clean on both builds (no
  `stack-buffer-overflow`), with `DECODE_OK=0`.
- `bash run-all.sh`: **13 PASS / 0 FAIL**, rc 0. Summary output is in
  `runs/run-all.out`; per-case traces are in `runs/*.out`.

The recorded logs include absolute paths of this checkout and process ids;
they are evidence of the observed run, not portable identifiers.
