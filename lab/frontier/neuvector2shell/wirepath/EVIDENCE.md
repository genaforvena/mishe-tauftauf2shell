# W278 — optimized real-object frame under the REST-valid wire message

Command: `bash lab/frontier/neuvector2shell/wirepath/frame.sh` -> **17 PASS /
0 FAIL**, rc 0. It consumes the messages regenerated by `wirepath/run.sh`
(now 20 PASS / 0 FAIL). Raw gdb/ASan logs and binaries stay in the ignored
`wirepath/out/`; this file keeps the normalized, address-independent facts.

Inputs, hashed at run time:

- real pinned `dp/dpi/sig/dpi_sig.c` SHA-256
  `1fbf0ba4aa731f8a92801002d2fe39141c2a88ea9a96d18507af47ae3303072b`,
  tarball SHA-256 `8827c5f0…48287`.
- verbatim pinned `dp_ctrl_bld_dlp` consumer in `gen/wirecall.c`, real
  `libjansson.so.4`; only logging and small helpers are local.
- REST-valid attack message: name 256 bytes, 16 patterns of 64 bytes
  (`a*` repeated 32), pre-expansion total 1024 bytes — all inside the
  controller limits at `controller/api/apis.go:140-144`.
- Chosen-byte variant uses `B*` repeated 32; same lengths, same REST limits.

## `-O0`, no stack protector (`out/frame-gdb-attack.log`)

`BUF=…d6e0 RBP=…df00 DELTA=2080`. Chosen wire pattern bytes
(`0x2a 0x61 0x2e` — `*`, `a`, `.`) are visible at `BUF+2048` through
`BUF+2055` (`/is; context body` tail follows); the process then faults at
`dpi_sig.c:657` with `len` overwritten (`0x74732f78`, ASCII `x/st`). At
that point saved RBP (`BUF+2080`) and return slot (`BUF+2088`) still hold
pointer-shaped values (`0x7fff…`, `0x5555…`), not chosen bytes. Safe message
reaches line 662 and completes `WIRECALL rc=0`.

## `-O2`, fortify disabled, no stack protector (`out/frame-o2-a.log`, `out/frame-o2-B.log`)

`BUF→RBP = 2096` bytes. The fault is at `dpi_sig.c:657`, after the pattern
`sprintf()` overwrites both saved frame words:

| wire pattern byte | saved RBP (`$rbp`) | return slot (`$rbp+8`) |
| --- | --- | --- |
| `a` (`0x61`) | `0x2a2e612a2e612a2e` | `0x2e612a2e612a2e61` |
| `B` (`0x42`) | `0x2a2e422a2e422a2e` | `0x2e422a2e422a2e42` |

Decoded, these are the chosen wire bytes `.*a.*a.*` / `.*B.*B.*`. Changing
the attacker-selected pattern byte changes the bytes in **both** saved RBP
and the saved return address at chosen offsets. Vulnerable object: safe
message `WIRECALL rc=0`. Fixed pinned source at `-O2`: attack message
`WIRECALL rc=0`. No process continues after the overwrite; it faults on the
next loop condition with the ASCII-filled pointers.

Negative result: with Ubuntu's default `_FORTIFY_SOURCE` left enabled, the
same `-O2` build aborts with `*** buffer overflow detected ***` from
`__sprintf_chk` (`out/frame-gdb-o2-attack.log`) before any chosen-byte
readback. Fortify was disabled only to measure the underlying frame.

## Ceiling

Chosen bytes at chosen offsets, including the saved return slot, are now
demonstrated in an optimized **real-object lab frame** driven by a
REST-valid controller-shaped message. This is still not a chosen address:
the bytes are ASCII regex text, not a valid code pointer. There is no live
enforcer binary, no REST/CRD endpoint, no pointer redirection, no benign
command and no rung-5 side effect. These byte values must not be reported
as pointer control or execution.
