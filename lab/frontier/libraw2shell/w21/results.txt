W21 results — file-chosen bytes in LIVE allocator metadata (2026-11-25 05:3xZ, author-side)

Question left open by W19: its heap walk found no live object after destimage,
but the chunk immediately after destimage is the top chunk. Does the OOB store
reach the top chunk's size field, and does the consumer's allocator later read
the bytes written there? Prediction recorded before the pad-16 run: a file-chosen
size-field value selects which glibc consistency check fires at a later free.

Method and pinned bytes
- Lab-only env MALLOC_TOP_PAD_=16777216 (also 67108864 for one control) keeps the
  whole OOB write span mapped, so xtrans_interpolate() finishes instead of
  SIGSEGV at :427. The env is a lab condition, not an image-controlled knob.
- Two inputs: w13/dead-target.input (sha256
  18b012c98809a9f4822a173ee591b046db3b6eb612326e30e259984467149e78, W13's
  pre-chosen triple) and a new w21/zero.input (sha256

  by the unchanged craft_uncompressed_poc.py from w21/zero.json (sha256
  cf7083cdabe8cb4d56d6f951547b575c0266ef2cdc8088065b932febbc8525ce):
  every raw sample 0, every LinearizationTable entry 0, WhiteLevel 65535.
- Unmodified -O0 dcraw_emu (sha256 ca941dae...) under w21/sizefield.gdb (sha256

  The size field is addressed as (char*)main_arena.top + 8, not main_arena.top+8:
  gdb pointer arithmetic on mchunkptr scales by sizeof(malloc_chunk).

Preserved probe error: the first probe (w21/tophdr.gdb, w21/postloop.gdb) used
main_arena.top + 8, which lands 384 bytes past the size field; its
0xdeadbeef9000 reading was OOB scratch content, NOT allocator metadata. Those
files are kept as negative evidence; the corrected probe is sizefield.gdb.

Conclusion and grade
The crafted image chooses the 48 low bits of the top chunk's live size field,
and the two file-chosen values select two different glibc checks in a later
free of the real dcraw_emu consumer. This is rung-4 control of live allocator
metadata, not a live application object, pointer, IP, marker or command side
effect. It does not reopen W19's object lane and is NOT rung 5. No grooming or
ASLR study: the heap layout is a lab env condition. Author-side only; no
witness verdict claimed. Replay: w21/replay.sh (one command, hash-checked).
All experiments local and loopback-free.
