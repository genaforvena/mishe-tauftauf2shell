## Build and observed results

Both sides: extract the pinned tarball, copy for the fixed side, apply the one
patch, then `autoreconf -fi` and configure with the public dependency-free
options (`--without-lame --without-sndfile --without-ffmpeg --without-twolame
--without-alsa --without-pulse --without-oss --without-magic --without-modplug
--without-mp3 --without-ogg --without-flac --without-opus --without-vorbis
--without-speex --without-amr --without-gsm --without-codec2
--disable-shared --enable-static`), CFLAGS `-g -O1 -fsanitize=address
-fno-omit-frame-pointer -static-libasan -no-pie`, LDFLAGS `-fsanitize=address
-static-libasan`, `make -j2`. Both binaries report `SoX_ng v14.8.1`.

## Limits and preserved negatives

- No plain non-ASan build was made locally; the minimal PoC's overflow may be
  hidden by allocator slack. The upstream reporter's abort used a long 4-bit
  block; that claim stays a claim, not a local observation.
- `v->size`/block-switch mechanism is read from the pinned source and the fix
  hunk; the stored `sox_sample_t` is ADPCM-derived, so arbitrary 32-bit values
  are NOT demonstrated.
- No chosen-offset readback, pointer overwrite, control-flow steering, benign
  command, socket, listener or daemon consumer. The CVE's "remote" wording
  presupposes a victim decoding an attacker-supplied file. Rung 4 and rung 5
  are NOT CLAIMED.
- GHSA affected/patched fields are UNKNOWN; version bounds come from the CVE
  record and the tags. Fixed tag 14.9.0 bundles other changes, so attribution
  uses the single patch only.
- Raw build logs, generated `.voc` files, source trees and binaries are
  gitignored; refetch commands and source hashes above let a witness rebuild
  from a clean archive.
