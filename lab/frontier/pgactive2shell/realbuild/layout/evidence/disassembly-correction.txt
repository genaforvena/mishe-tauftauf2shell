The earlier note identified offset -32 (rbp-0x70-32 = rbp-0x90) as "the
saved return address" because the downward search for PRE matched there
first. That slot is below the frame pointer and is not this function's
return-address slot; what places the copy there was not determined and
stays UNKNOWN. The real return-address slot at +120 is overwritten:
in the N=256 LAYOUTWIN line, bytes at offsets 104..127 alternate 41 5a,
so offset 120 = 0x41 and 121 = 0x5a.

Outcome
-------

non-empty trailing name assigns the fifth conversion, sscanf returns 5,
and the pinned `!= 4` check sends every overflowing input to
elog(ERROR)'s longjmp. The overwritten return-address slot at +120 and
canary at +72 are therefore never consumed. The saved-pointer/IP route
stays closed; the reason is the longjmp, not a return address below the
buffer. No cluster was started for this check; no host setting changed.
