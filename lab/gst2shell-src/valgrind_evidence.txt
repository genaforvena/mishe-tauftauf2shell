INTERPRETATION
  Confirmed memory corruption (evidence-rung 3) in the REAL remote path:
  attacker SDP sets encoding-params=(string)1000; decodebin auto-plugs the
  shipping GstRtpL8Depay; set_caps (a sticky event sent via gst_pad_send_event
  from libgstplayback) performs 4-byte stores past the 1,016-byte GObject
  allocation of the depay element.

LIMIT / HONEST CAVEAT
  The valgrind build has no debug info for the shipping plugin, so the write
  frames print as `??? (in libgstrtp.so)`; the instruction was NOT symbolicated
  to a function name in this run. An attempted offset mapping landed in
  gst_rtp_L8_pay_setcaps rather than the write and was discarded, not claimed.
  Attribution to the vulnerable function rests on the source-level single
  assignment (`gstrtpchannels.c:308-309`), the earlier gdb symbolication of
  the direct set_caps fault (`gst_rtp_L16_depay_setcaps+480`), the 4-byte
  stride, and the N=8 clean control. The written VALUE is still the fixed
  compile-time constant -3 / 0xfffffffd; no chosen-byte control.
